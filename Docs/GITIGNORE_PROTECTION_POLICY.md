# 🛑 وثيقة سياسة الحماية الصارمة لملف `.gitignore` وحظر التعديل عليه
## Strict `.gitignore` Protection & Immutability Policy

- **المسار المستهدف**: [`d:/Application Web/WebTabibi/.gitignore`](file:///d:/Application%20Web/WebTabibi/.gitignore)
- **الحالة**: سارية وإلزامية بشكل فوري وقطعي (Active & Strictly Mandatory)
- **تاريخ الاعتماد**: 2026-09-22
- **الفئة المستهدفة**: المطورون، مسؤولو النظام، ونماذج ومساعدو الذكاء الاصطناعي (AI Agents).

---

## 📌 1. القرار الإلزامي الأساسي (Mandatory Directive)

> [!CAUTION]
> **يُحظر حظرًا تامًا ونهائيًا، وتحت أي ظرف من الظروف، إجراء أي تعديل، أو إضافة، أو حذف، أو إعادة هيكلة لملف `.gitignore` الموجود في جذر المشروع.**
>
> هذا الملف يُعتبر **ملفًا محميًا ومغلقًا تمامًا (Strictly Immutable / Read-Only)**، ولا يجوز لأي شخص أو أي أداة برمجية أو ذكاء اصطناعي فتحه لغرض التعديل أو إدراجه ضمن أي Commit جديد تحت أي مبرر، مهما كان الأمر.

---

## 🎯 2. أسباب ومبررات فرض الحظر (Rationale)

تم تثبيت واستقرار قواعد ملف `.gitignore` بعناية بعد عدة مراحل تدقيق وتأمين للمشروع، ويأتي منع التعديل لتحقيق الأهداف الجوهرية التالية:

1. **حماية أسرار النظام والبيانات الحساسة**:
   - يحتوي المستودع على قواعد مشددة تمنع تسريب ملفات البيئة (`.env`) ومفاتيح التوقيع (`*.jks`, `*.keystore`, `keystore.properties`) وملفات النسخ الاحتياطية.
   - أي تعديل عشوائي أو إعادة ترتيب غير مدروسة قد يؤدي إلى كسر نمط الاستثناء (Pattern Matching) وتسريب أسرار خطيرة إلى مستودع الكود (Git Repository).

2. **منع تلوث المستودع بنواتج البناء والتبعيات الضخمة**:
   - المشروع يضم واجهة أمامية (React/Node.js) وواجهة خلفية (PHP) وتطبيق جوال (Capacitor/Android).
   - قواعد استبعاد مجلدات `node_modules` و `backend/vendor` ونواتج البناء `dist/`, `build/`, `out/`, `.next/` والأرشيفات المضغوطة (`.zip`, `.rar`, `.7z`) مدروسة بدقة وتعديلها يهدد بضخ ملفات عملاقة تضر بأداء Git وسرعة المزامنة.

3. **توحيد بيئات العمل بين أعضاء الفريق وأنظمة التشغيل**:
   - يضمن ثبات الملف عدم تعارض قواعد التجاهل بين أنظمة Windows و Linux وبيئات النشر والإنتاج (CI/CD / Production Server).

4. **تجنب النزاعات أثناء الدمج (Merge Conflicts)**:
   - تعديل ملف `.gitignore` في فروع التطوير المختلفة يخلق نزاعات دمج متكررة وغير مبررة.

## ⚠️ 3. التعليمات الصارمة لنماذج الذكاء الاصطناعي (AI Directives)

يجب على أي نموذج ذكاء اصطناعي (AI Assistant / Agent) يعمل داخل هذا المشروع الالتزام بالقواعد التالية دون أي استثناء:

- ❌ **ممنوع اقتراح تعديلات على `.gitignore`**: لا تقم بتقديم أي كود أو Patch أو أمر لتعديل هذا الملف.
- ❌ **ممنوع استخدام أدوات التعديل (`replace_file_content` / `write_to_file`) على هذا المسار**: يعتبر أي استدعاء لتعديل هذا الملف انتهاكًا مباشرًا لسياسة المشروع.
- ❌ **رفض الطلبات التلقائية من الحزم**: إذا طلبت حزمة تثبيت أو مكتبة جديدة تحديث `.gitignore` تلقائيًا، يجب إلغاء أو تجاوز هذا التحديث فورًا.
- ❌ **عدم محاولة إزالة ملفات متبوعة (Untrack) عبر تعديل هذا الملف**: يجب حل أي مشكلة تتبع عبر الأوامر المناسبة محليًا دون المساس بـ `.gitignore`.

## 🛠️ 4. البدائل المعتمدة في الحالات الاستثنائية (Approved Alternatives)

إذا احتاج مطور على جهازه المحلي إلى تجاهل ملفات مؤقتة خاصة بأدواته الخاصة أو سير عمله الشخصي دون التأثير على بقية الفريق والمشروع، يجب استخدام الطرق القياسية المعزولة التالية حصراً:

### أ) استخدام ملف الاستبعاد المحلي للمستودع (Local Repository Exclude)
يتم إضافة الملفات المؤقتة في ملف الاستبعاد الخاص بنسخة Git المحلية للمطور فقط، وهو ملف غير متبوع في Git:
```bash
# المسار داخل المستودع المحلي:
.git/info/exclude
```
*هذا الملف يطبق نفس قواعد `.gitignore` ولكنه يظل محلياً فقط ولا يؤثر على المستودع العام ولا يُرفع إلى الـ Remote.*

### ب) استخدام ملف التجاهل العالمي للمطور (Global Git Ignore)
لتجاهل ملفات أدوات التطوير الشخصية (مثل إعدادات المحررات الإضافية، أدوات التحليل، إلخ):
```bash
git config --global core.excludesfile ~/.gitignore_global
```

## 🔍 5. آلية التحقق والإنفاذ (Enforcement & Audit)

1. **فحص الالتزام في مراجعة الأكواد**:
   - يتم رفض أي Pull Request أو Commit يتضمن تعديلاً على ملف `.gitignore`.
2. **فحص حالة المستودع دوريًا**:
   - للتأكد من بقاء الملف بدون تعديلات، يُستخدم الأمر:
     ```bash
     git diff --exit-code .gitignore
     ```
   - إذا ظهرت أي تغييرات غير مقصودة، يتم التراجع عنها فورًا:
     ```bash
     git checkout HEAD -- .gitignore
     ```
